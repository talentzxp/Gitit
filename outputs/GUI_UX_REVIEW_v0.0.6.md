# GitIt v0.0.6 Human-Centered Visualization Review

## 1. 当前 GUI 解决的问题

GitIt Desktop 保持对 GitIt.Core 的单向依赖：它只呈现 Core 已输出的家族、关系、证据、警告、参与者和语义 Diff，不在界面层重算分数、补造父版本或猜测作者。这样用户看到的每个判断仍可回溯到 Core 证据。

## 2. 新增视图

- 家族名称优先采用文件名的共同主干，其次采用 Office 内标题；不能可靠命名时使用中性名称。
- 版本血缘图将强或中等关系、弱关系、仅相关未证实关系和冲突关系分别以实线、虚线、点线问号和红色线条呈现。
- 节点同时显示文件名、文件类型、时间、置信度、关系状态、参与者和重复或警告徽章。
- 时间线按 Core 可用时间呈现文件、参与者、关键变化与状态；编辑环境明确显示为 Core 未提供此证据，避免伪造 Word 或 WPS 来源。
- 右侧面板分为摘要、支持证据、疑点、警告、语义 Diff 与技术来源，默认先展示可理解结论。
- Diff 使用旧值与新值并排呈现；纯删除使用红色，纯新增使用绿色。

## 3. 当前仍存在的问题

- 图布局目前是适用于 PoC 的确定性分层布局，超大文件家族会需要缩放、搜索和更成熟的自动布局。
- 关系线的颜色和线型可以继续接受可用性测试；目前目的优先是将确定关系与不确定关系明显分开。
- 时间线的关键变化为 Core 语义 Diff 的简述，不是完整的人类编辑故事。

## 4. 未解决限制

- Core 尚未输出可靠的编辑器环境，因此 GUI 不显示推测的 Word、WPS 或其他应用来源。
- Creator、LastModifiedBy、修订作者和评论作者仍是 Office 包内字符串线索，不是身份认证结果。
- RelatedButUnproven 只表示文件属于同一演变脉络，不能解释为确认的父子版本关系。
- Real Corpus 仍为空，状态保持 WAITING FOR MANUAL CORPUS。

## 5. 隔离演示与验证

- `dotnet run --project src/GitIt.Benchmarks -- demo` 已生成 31 个仅用于 GUI 的合成 Office 文件，覆盖主链、分支、重复、未证实相关和警告条件。
- 构建已通过：0 个警告，0 个错误；全部 17 项测试通过。测试覆盖家族名、时间线和从 Core 关系进入证据及 Diff 的路径。
- Windows 桌面程序已完成一次隐藏启动检查，并保持运行后正常退出；本轮没有将该检查当作人工视觉验收或真实语料验证。
- 此次未将合成演示结果解释为真实 Word、WPS 或协作流程验证。

## 6. 结论

Recommendation: READY FOR REAL CORPUS TEST

这表示 GUI 已适合接收人工授权的真实语料测试；不表示 Real Corpus Gate 已通过，也不表示当前 GUI 已达到发布级产品质量。
